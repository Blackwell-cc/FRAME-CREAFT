# Clean Reference Media Design

## เป้าหมาย

ทำให้การ์ด Production Reference และหน้ารายละเอียดแสดงรูปจริงเต็มเฟรมอย่างสะอาด โดยไม่มีช่องเหลื่อม รหัสย่อ ตัวเลข หรือเส้น Grid ทับภาพ และให้พฤติกรรมนี้ใช้กับรูปที่เพิ่มในอนาคตโดยอัตโนมัติ

## กติกาการแสดงผล

- เมื่อรายการมี `imageUrl` ให้เข้าสู่โหมดมีรูปจริง
  - รูปต้องปิดพื้นที่ visual ทั้งหมดด้วย `object-fit: cover`
  - รูปต้องชิดขอบเฟรม ไม่มีแถบหรือช่องว่างด้านล่าง
  - ไม่แสดง `visual-code`, `visual-index`, `viewfinder-grid` หรือรหัสย่อขนาดใหญ่ในหน้ารายละเอียด
  - ใช้พฤติกรรมเดียวกันกับภาพเริ่มต้นและภาพที่ผู้ใช้เพิ่มภายหลัง
- เมื่อรายการไม่มี `imageUrl` ให้คงกราฟิก Monochrome สำรอง รหัส และ Grid แบบปัจจุบัน เพื่อให้การ์ดไม่ว่าง

## สาเหตุของปัญหาปัจจุบัน

กฎเอฟเฟกต์ปุ่มกลางกำหนด `position: relative` ให้ลูกโดยตรงทุกตัวของปุ่ม ซึ่งมี specificity สูงกว่ากฎตำแหน่งรูปใน `.technique-visual` จึงเปลี่ยนรูปจากชั้น `absolute` ให้กลับเข้า document flow และเกิดพื้นที่เหลื่อมด้านล่าง ส่วนรหัสและ Grid ถูก render โดยไม่ตรวจว่ามีรูปจริงหรือไม่

## การออกแบบส่วนประกอบ

### TechniqueCard

- ใช้ `imageUrl` เป็นเงื่อนไขเดียวในการเลือกโหมด
- เมื่อมีรูป ให้ render เฉพาะรูปภายในพื้นที่ visual
- เมื่อไม่มีรูป จึง render `viewfinder-grid`, `visual-code` และ `visual-index`
- ปรับ selector เอฟเฟกต์ปุ่มไม่ให้เปลี่ยนตำแหน่งลูกของ `.technique-visual`

### Detail Dialog

- ใช้ `mediaUrls[detail.id]` เป็นเงื่อนไขเดียวกับการ์ด
- เมื่อมีรูป ให้ render เฉพาะรูปโดยไม่มี Grid และรหัสย่อขนาดใหญ่
- เมื่อไม่มีรูป ให้คง fallback visual และรหัสเดิม

### CSS

- รูปใน visual ใช้ `position: absolute`, `inset: 0`, `width: 100%`, `height: 100%` และ `object-fit: cover`
- จำกัดกฎยกชั้นลูกของปุ่มให้ไม่ครอบคลุม `.technique-visual`
- ไม่ใช้การแก้เฉพาะ `shot-close-up` สำหรับโครงสร้าง visual เพื่อให้รายการใหม่ได้รับพฤติกรรมเดียวกัน
- คง class รักษาสีธรรมชาติของ Close-Up ตามขอบเขตเดิม

## Data Flow

1. ระบบรวมภาพเริ่มต้นกับภาพที่บันทึกในเครื่องเป็น `mediaUrls`
2. `CategorySection` ส่ง `imageUrl` ให้ `TechniqueCard`
3. การ์ดเลือกโหมดมีภาพหรือ fallback จากการมีอยู่ของ `imageUrl`
4. หน้ารายละเอียดอ่าน URL จาก key เดียวกันและเลือกโหมดด้วยกติกาเดียวกัน

## การทดสอบ

- เพิ่ม regression test ยืนยันว่าการ์ดที่มีภาพไม่มี Grid รหัสย่อ และตัวเลข overlay
- ยืนยันว่าหน้ารายละเอียดที่มีภาพไม่มี Grid และรหัสย่อขนาดใหญ่
- เพิ่มกรณีรายการที่ไม่มีภาพ เพื่อยืนยันว่า fallback overlay ยังคงอยู่
- ตรวจ CSS ว่ารูปยังเป็น absolute cover และกฎเอฟเฟกต์ปุ่มไม่ override พื้นที่ visual
- รัน unit tests, TypeScript, lint และ production build ทั้งชุด

## เกณฑ์สำเร็จ

- Close-Up แสดงภาพเต็มเฟรม ไม่มีแถบเหลื่อมด้านล่าง
- ไม่มี `CU`, ตัวเลข หรือเส้น Grid บังภาพทั้งบนการ์ดและหน้ารายละเอียด
- ภาพที่เพิ่มในอนาคตได้พฤติกรรมเดียวกันโดยไม่ต้องเพิ่มเงื่อนไขราย ID
- รายการที่ไม่มีภาพยังคง fallback visual เดิม
